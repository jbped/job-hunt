# design-sync notes — job-hunt-ui

## Shape and layout

- Package shape (no Storybook). The package root is `ui/`; run every converter
  command from there, not the repo root. `.design-sync/` and `.ds-sync/` live
  under `ui/` so config paths stay package-relative.
- `buildCmd` is `npm run build:lib` (`vite.lib.config.ts`), which emits
  `dist/index.js` + `dist/styles.css` and per-file `.d.ts` under
  `dist/components/ui/`. The app build (`npm run build`) is a different target
  and does not produce the library entry.

## Component count

- The converter reports **210 components, not 40**. That is correct: shadcn's
  API is compound, so `card.tsx` alone exports Card, CardHeader, CardTitle,
  CardAction, CardDescription, CardContent and CardFooter. Do not "fix" this
  with `componentSrcMap` exclusions — they are all real exports the design
  agent should be able to use.

## Grouping

- Without doc frontmatter every component lands in one flat `general` group.
  `docs/design-system/<Name>.md` stubs (frontmatter `category:` only) provide
  the 7 groups, and are generated by `npm run gen:ds-docs` from a file→category
  map in `scripts/gen-ds-docs.mjs`. **Re-run that script after adding or
  removing a shadcn component**, or the new component falls back to `general`.

## Base colour

- The theme is shadcn 4's **`mist`** base colour. This took some finding, and
  the next person will hit the same wall: shadcn 4 **dropped `slate`**
  entirely, and replaced the old base-colour flag with named style presets
  (Nova, Vega, Maia...). The CLI's local `PRESET_BASE_COLORS` list still
  contains `gray`, but the registry rejects it —
  `Invalid enum value. Expected 'neutral' | 'stone' | 'zinc' | 'mauve' |
  'olive' | 'mist' | 'taupe', received 'gray'`. Trust the registry, not the
  CLI's list.
- `mist` was chosen as the nearest surviving cool grey to slate (hue ~214-228
  vs slate's ~257; `zinc` leans violet, `neutral` is achromatic).
- `init` was run non-interactively with an encoded preset code
  (`shadcn init -b radix --preset <code>`); the code is produced by
  `encodePreset()` from the CLI's own `dist/preset/index.js`. There is no
  `shadcn preset encode` command.
- All seven stock palettes are compiled into `src/base-colors.css`, generated
  from `https://ui.shadcn.com/init?baseColor=<name>` (the old
  `/r/colors/<name>.json` endpoint also still responds). They are selected at
  runtime by a `data-base-color` attribute on `<html>`; `mist` is also the
  bare `:root` default.

## Fonts

- `src/design-system.css` deliberately does NOT import the web font;
  `src/index.css` (the app entry) does. This keeps ~291kB of base64 Inter out of
  the library stylesheet. The consequence is that the DS bundle has no
  `@font-face` of its own, so `cfg.extraFonts` points at
  `node_modules/@fontsource-variable/inter/index.css` to ship the font. If you
  ever see `[FONT_MISSING]`, that config entry is why it normally doesn't fire.

## The utility safelist (important)

- Designs rendered from this bundle receive `styles.css`'s import closure and
  **no Tailwind compiler**. Only utilities physically present in
  `_ds_bundle.css` resolve. The compiled component CSS alone covers just the
  classes our own components use — `mb-4`, `max-w-md`, `text-lg`,
  `font-semibold`, `space-y-4` and `shadow-sm` were all absent.
- `src/design-system.lib.css` therefore wraps `design-system.css` with a
  `@source inline(...)` safelist of the common layout/spacing/typography/colour
  families, and the barrel imports the `.lib` file. The app imports
  `design-system.css` directly and does not pay for the safelist (verified: no
  safelist-only class appears in the app bundle).
- **If you widen the class vocabulary in `conventions.md`, widen the safelist
  in the same commit** — otherwise the design agent will write classes that
  silently do nothing.

## Known render warns

- `BreadcrumbEllipsis / Alone` renders as a bare three-dot glyph and is
  legitimately thin — the component is a single ellipsis. The `CollapsedTrail`
  cell shows it in a real breadcrumb.
- The four components that were `[RENDER_BLANK]` on the first pass (Progress,
  Checkbox, BreadcrumbEllipsis, SidebarMenuSkeleton) are near-empty by nature
  when unauthored. All four now have authored previews.

## Composition gotchas learned while authoring

- `Message` is a layout wrapper only. Its visible chat styling comes from a
  `Bubble` placed inside `MessageContent`, and `align="end"` only moves children
  that carry a `data-slot`. A preview with plain text children renders thin and
  shows no alignment difference.
- `MessageAvatar` is an empty rounded box — give it children (initials) or it
  has zero height.
- `DropdownMenuContent` needs an explicit width (`className="w-56"`, shadcn's
  own docs idiom) or item labels wrap mid-phrase.
- `SelectContent` needs `position="popper"` in a preview, else the open list
  covers its own trigger.
- Overlay components need `cfg.overrides.<Name>.cardMode = "single"` plus a
  viewport, and `Table` needs `cardMode: "column"`.

## Re-sync risks

- **`shadcn add` regenerates component files.** Anything hand-patched is lost:
  today that is `src/components/ui/sonner.tsx`, which was moved off
  `next-themes` onto this app's own appearance store (`src/lib/theme.ts`).
  Re-check it after any `shadcn add`/`--overwrite`.
- **Grouping rots on component add** — see the `npm run gen:ds-docs` note above.
- **React 19 is required.** shadcn 4 components are plain function components
  with no `forwardRef`; on React 18 Radix's refs are silently dropped. There is
  a smoke test at `src/components/ui/__tests__/smoke.test.tsx` guarding this.
- **`@source not` does not work in Tailwind 4.3.3** (tried and removed). As a
  result the app bundle carries a small number of utility classes used only by
  `.design-sync/previews/*.tsx` (~1kB gzip). Harmless; revisit if Tailwind fixes
  the directive.
- **Only the toolchain here was verified**: Node 22.23.2, npm 12.0.2,
  playwright 1.62.1 with chromium 1234, shadcn CLI 4.20.1. The shadcn registry
  is fetched over the network at `add` time and its output can drift.
- The converter's `[DTS_STYLE_SYSTEM]` line (filtering `@types/react`
  CSS-shorthand props) is expected and non-blocking.
